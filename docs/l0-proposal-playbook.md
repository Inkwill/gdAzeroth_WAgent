# L0 立项书撰写实战手册 · Proposal Playbook

> 立项书方法论 v1（2026-08-31 实战沉淀，案例：Green Tide T-gt-01 重构版）。
> 场景：L0 立项需求 → 用 10 章结构产出立项书（定位/玩法核心/范围锁定）。
> 前置文档：gdMain `entry/workflow/plan-mode.md`（要素问询流程）· `templates/reqs/plan/L0-project-init/`（要素模板）· gdMain `entry/workflow/reqflow.md` §3.1（L0 验收锚点）。
> 实战案例：`projects/green-tide/T-gt-01-project-brief.md`（重构版，10 章全文范例）。

---

## 1. 立项书三重使命（先立魂，再动笔）

写立项书前先问自己三件事——这决定全文结构：

| 使命 | 要回答的问题 | 落在哪一章 |
|------|-------------|-----------|
| **立魂** | 这游戏一句话是什么？玩家为什么非玩不可？ | ① 定位 · ⑥ 叙事 |
| **锁范围** | 首版做什么？**更关键：不做什么？** | ⑤ 范围边界 |
| **定验收** | 怎么算成功？数据不达标怎么办？ | ⑨ KPI 闭环 · ⑩ 验收锚点 |

> 铁律：三使命缺一，立项书就是"提案"不是"立项书"——魂不立则全文无主线，范围不锁则排期必漂移，验收不闭环则失败无退路。

## 3. 逐章撰写要点

### ① 一句话定位与三核卖点
- **一句话定位**：`XX类型 + 核心玩法动词 + 情感承诺`。句式参考："休闲化末世生存『一键治愈』点击游戏——每一次点击都是废墟的解药"。
- **三核卖点**：每条卖点 = 机制名 + 玩家体验 + 对标/依据。数量上限 3——多了就不是卖点。
- **核心情感体验**：一句话情绪主张（治愈感/爽感/掌控感），全文所有系统设计都要能回溯到它。

### ② 市场与用户画像
- 赛道判断用表格（维度/判断/**依据性质**）——**没有公开精确数据就必须标"待验证假设"**，禁止断言式写作。
- 用户画像给占比 + 画像 + 共同特征；画像要与④玩法逐项对齐（用户怕硬核 → 玩法就剥离焦虑机制）。
- 末尾必须放**数据假设声明**：哪些是方向性假设、验证责任落在哪（Soft Launch）。

### ③ 竞品对照矩阵与差异化
- 矩阵至少 5 个产品：结构对标 + 题材对标 + 2-3 个大盘参考，列：题材/复杂度/变现/用户盘/**对本项目的意义**。
- 差异化两条：吸收什么（结构）+ 反向什么（题材焦虑点）。"反向差异化"是最强论证。

### ④ 玩法闭环与核心系统
- 闭环用 ASCII 或 mermaid 一图流：系统 A → 产出 → 系统 B → 反馈 → 回 A。
- 核心系统给**可验收规格**（棋盘格数、生成器数量、道具链 Lv.1-4、解锁时机）——不给规格的系统描述等于没写。

### ⑤ 范围边界（全篇最易漏，最该写）
- ✅ 首版锁定清单：**逐条可验收**（"7×9 棋盘 + 5 大生成器"优于"核心玩法"）。
- ❌ 不在首版清单：把团队可能忍不住做的东西**先写死**（后续章节、社交、养成树、多语言、硬核机制）。
- 加一句**边界铁律**："任何新需求先问『属于 5.1 吗』，否则默认不进首版"——这句是给排期章节的护身符。

### ⑥ 叙事与内容结构
- 人设给：身份/动机/性格/视觉锚点，主角 2 个封顶（立项期）。
- **情感弧线表**（章节/场景数/弧线/落点）+ 角色弧一句话——把"清单"升级为"结构"，才能判断内容够不够撑长留。
- 内容清单表格化（编号/名称/叙事点），叙事点要有画面细节（"墨绿色围巾""红玫瑰种子"）。

### ⑦ 商业化与经济流转
- 变现结构给比例 + 每个付费点的**玩家价值**（痛点在哪）。
- **经济流转框架**（来源 → 双币 → 消耗）必画——没有闭环，付费点就是无根之木。
- 立项期商业化为**框架级**：定价锚点/数值阶梯留给数值分控（详见 §4 边界）。

### ⑧ 排期与里程碑验收
- 阶段表给：阶段/内容/**里程碑验收要点（做到什么算过）**。
- 必写**退出点**：哪个里程碑不过就砍什么（"M5 不过 → 砍后 5 场景保闭环"）。
- 立项期排期标注"方向性，由总控/团队对齐后生效"。

### ⑨ KPI 因果链与止损线
- 目标值表格（指标/目标/采集点）——留存、ARPPU 之外补过程指标（CPI/ROAS/LTV）。
- **KPI → 设计因果链**是本章灵魂：每个 KPI 必须写"哪个设计支撑它、链路是什么"——没有因果链的目标值只是愿望。
- **止损线（Kill Criteria）**：数据低于什么值 → 判定哪个环节失效 → 做什么动作。触发即回炉，不闷头加量。

### ⑩ 风险闭环与验收锚点
- 风险表五列：风险/概率/影响/应对/**责任人**——SWOT 的 T 必须在这里闭环。
- 文档验收锚点表（锚点/内容/状态）：怎么算过关，写给自己也写给验收方。

## 4. 与 gd 体系对齐

### 4.1 plan-mode 要素 → 章节映射（锁定要素必须全部落进正文）

| plan.md 要素 | 落点章节 | 说明 |
|--------------|----------|------|
| positioning | ①②③ | 一句话定位 + 市场佐证 + 竞品差异 |
| monetization | ⑦ | 变现结构 + 经济流转 + 联动点 |
| art_style_visual | ④（承接） | 画风基准详述归 T-gt-03 美术概念图 |
| art_style_color | ④（承接） | 色彩体系详述归 T-gt-03 |
| art_style_character | ⑥ | 双主角人设 + 羁绊 |
| visual_transformation | ④⑥ | 蜕变视觉节奏 + UA 素材源 |
| scope | ④⑤ | 玩法规格 + ✅/❌ 双清单 |

### 4.2 L0 验收锚点命中（reqflow §3.1）
L0 类型验收只查「定位 / 玩法核心 / 范围」三类标记命中——10 章结构天然覆盖且更强（定位=①②③，玩法核心=④⑥⑦，范围=⑤，外加验证闭环=⑨⑩）。**重构/扩写不得破坏任一锚点的可检索性**（章节标题保留关键词）。

### 4.3 分控边界（哪些不写进立项书）
| 内容 | 归属 | 立项书处理 |
|------|------|-----------|
| 定价锚点/数值阶梯/体力时长 | forge（GMD） | ⑦ 只写框架 + 联动点，标注"详细模型见 T-gt-02" |
| 画风基准/色彩/人设详图 | azeroth（T-gt-03） | ④⑥ 概述，指向美术概念图文档 |
| 最终排期/资源调配 | 总控（GPM） | ⑧ 标注"方向性，待总控对齐" |
| 可交互原型/玩法 demo | greymaze（PLAgent） | 立项书不涉及 |

## 5. 验收自检清单（写完后逐条过）

- [ ] 第一屏有**一句话定位**（不是机制罗列）
- [ ] 有**核心情感体验**，且④⑦的每个系统都能回溯到它
- [ ] 三核卖点 ≤ 3 条，每条有机制+体验+依据
- [ ] 市场论断有出处，或已标注"待验证假设"并有**数据假设声明**
- [ ] 竞品矩阵 ≥ 5 产品，有"对本项目的意义"列
- [ ] 核心系统有**可验收规格**（格数/数量/等级链）
- [ ] 有 **❌ 不在首版清单** + 边界铁律
- [ ] 叙事有**情感弧线表**而非纯清单
- [ ] 商业化有**经济流转框架**（来源→消耗）
- [ ] 排期每阶段有**验收要点**，有**退出点**
- [ ] KPI 有**因果链**（哪个设计支撑）和**止损线**（低于多少怎么办）
- [ ] SWOT/风险表的威胁有**应对 + 责任人**闭环
- [ ] 术语全文统一（无"美除/绿潮/废土"混用类漂移）
- [ ] plan.md 全部 locked 要素在正文可检索到
- [ ] 有**文档验收锚点表**（怎么算过关）

## 6. 常见坑（实战提炼）

| 坑 | 表现 | 解法 |
|----|------|------|
| 定位埋没 | 第一章直接写市场，无 elevator pitch | ① 先立魂，市场只做佐证 |
| 断言式数据 | "赛道走高""CTR 极高"无出处 | 标注来源或"待验证假设" + §2.3 声明 |
| 缺范围 ❌ 清单 | 只写做什么，不写不做什么 | §5 双清单 + 边界铁律 |
| KPI 无闭环 | 只有目标值，无因果链/止损线 | §9.2 因果链 + §9.3 Kill Criteria |
| 排期无验收 | M1-M10 排了，没写"做到什么算过" | §8 里程碑验收要点 + 退出点 |
| 叙事清单化 | 10 场景只是列表 | §6.2 情感弧线表 + 角色弧 |
| 竞品只列 2 个 | 对标产品太少，无大盘参照 | §3.1 矩阵 ≥ 5 产品 |
| 术语漂移 | 同一概念多种叫法（美除废土/废土/末世） | 动笔前列术语表，全文统一 |
| ASCII 图错位 | md 渲染下定位图/排期图乱 | 简单用表格，复杂用 mermaid |
| 越界写数值/排期 | 立项书塞定价表、详细排期 | §4.3 分控边界，框架级 + 指向 |

## 7. 边界与演进

- 立项书是**概念层切片**（display + rule 交汇）：锁定位/范围/框架，不产数值、不产实现、不产美术资产。
- **数据假设必须验证**：§2.3 声明的事项在 Soft Launch 用真实数据校验，证伪即触发 §9.3 止损线。
- 演进预留：① 模板化——10 章结构可落为 `templates/proposal-skeleton.yaml`（对标 worldview-skeleton）供 `gd-wa proposal new` 使用；② 章节级要素问询——对齐 plan-mode，各章要素进 front-matter 锁定；③ 竞品矩阵数据化——接入外部数据源后由"定性对照"升级为"定量对照"。
